# ucSim wiring for the loadable-hw plugin loader

These are the changes to the **ucSim source tree** that turn on runtime plugin
loading. The plugin sources themselves (`hwload.cc` / `hwloadcl.h`) live in
`../core-additions/` and are copied into `src/core/sim.src/`.

Verified against Daniel Drotos' ucSim (the `master` checkout used by this
project; `s51` / `ucsim_51`). Built and tested end-to-end on 2026-09-14.

## 1. Drop in the loader sources

```bash
cp core-additions/hwload.cc  <ucsim>/src/core/sim.src/hwload.cc
cp core-additions/hwloadcl.h <ucsim>/src/core/sim.src/hwloadcl.h
```

## 2. Add the object to the sim.src build

`<ucsim>/src/core/sim.src/objs.mk` — append `hwload.o`:

```diff
 OBJECTS         = stack.o mem.o sim.o itsrc.o brk.o arg.o itab.o \
 		  guiobj.o uc.o hw.o simif.o serial_hw.o port_hw.o dreg.o \
-		  iwrap.o var.o vcd.o pc16550.o
+		  iwrap.o var.o vcd.o pc16550.o hwload.o
```

## 3. Register the `loadhw` command

`<ucsim>/src/core/sim.src/uc.cc` — include the header near the other cmd
includes:

```diff
 #include "cmd_uccl.h"
+#include "hwloadcl.h"
```

…and register the command in `cl_uc::build_cmdset` (right after the `file`/
`load` command, since `load` is already an alias of `file`):

```diff
   cmdset->add(cmd= new cl_file_cmd("file", 0));
   cmd->init();
   cmd->add_name("load");

+  cmdset->add(cmd= new cl_loadhw_cmd("loadhw", 0));
+  cmd->init();
+  cmd->add_name("insmod");
+
   cmdset->add(cmd= new cl_dl_cmd("download", 0));
```

## 4. Link flags: export symbols + libdl

The plugin `.so` is left with undefined references to `cl_hw`/`cl_uc`/
`register_cell`; they must resolve back into the running `ucsim_51`. Add
`-rdynamic` to the link and `-ldl` for `dlopen`.

`common.mk` is generated by `./configure`, so the durable fix is in the build
inputs (`configure.in` / `*.mk.in`). For a local build, edit the generated
`<ucsim>/src/common.mk`:

```diff
 WINSOCK_AVAIL   = 0
-LDFLAGS		=
+LDFLAGS		= -rdynamic
```

```diff
 UCSIM_LIBS	= -lmotorola -lsim -lucsimutil -lgui -lcmd -lsim \
-		  $(CURSES_LIBS) $(LIBS)
+		  $(CURSES_LIBS) $(LIBS) -ldl
```

(For a proper upstream change, add `-rdynamic` to `LDFLAGS` and `-ldl` to the
per-sim `UCSIM_LIBS` in the `.in` templates so `./configure` regenerates them.)

## 5. Build

```bash
cd <ucsim>
make -C src/core/sim.src     # builds libsim.a with hwload.o
make -C src/sims/s51.src     # links ucsim_51 with -rdynamic ... -ldl
```

## 6. Use

```bash
# build the example plugin (see ../example/)
../export-sdk.sh <ucsim> ../sdk
make -C ../example                 # -> demo_hw.so, loopback.so

# load at runtime
ucsim_51 -t 51
> loadhw "../example/demo_hw.so"        # alias: insmod
load hw: .../demo_hw.so loaded (id_string=demohw)
> set hardware demohw ping
demohw: set_cmd reached (runtime-loaded plugin OK)
```

## Notes / gotchas (verified)

- **Do not also compile the same module in.** ucSim's `set hardware <name>`
  argument resolver (`cl_cmd_sym_arg::as_hw`, `core/sim.src/arg.cc`) requires
  the `id_string` prefix match to be **unique**; if a module with the same
  `id_string` is both compiled in *and* loaded, `as_hw` returns "no hw". This
  is why the reference test uses `demo_hw.so` (unique id `demohw`) rather than
  the already-compiled-in `loopback`.
- **C++ ABI boundary.** A plugin `.so` is only compatible with a `ucsim_51`
  built from the same headers / compiler / `./configure` options. The
  `ucsim_hw_abi()` gate catches gross mismatches but is not a compatibility
  guarantee — re-export the SDK and rebuild plugins after a ucSim bump.
- **Load order.** A runtime-loaded module is `add_hw`'d after the core, so its
  `read()` wins on cells it registers (last operator wins) — same rule as the
  compile-in modules. If a module must intercept the very first fetch, load it
  before `run`/`reset`.
